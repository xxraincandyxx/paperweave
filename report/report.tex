\begin{abstract}
学术论文篇幅长、结构复杂、术语密集，读者难以快速把握研究主题、论证路径与局限。本文报告研脉（PaperWeave）系统的设计与实现：该系统将文本型学术论文 PDF 一键转换为带证据溯源的 Mermaid 思维导图与可离线打开的交互式 HTML 看板，覆盖\textbf{页级解析、来源分块、大模型结构化分析、证据核验、主题合并、导图校验与单文件导出}七个阶段。系统以归一化摘录匹配支撑证据回溯，以完整性校验防止节点静默丢失，并在真实 Chromium 内核中验证 Mermaid 语法后内嵌全部渲染资源，保证看板断网可用。我们在 macOS 与 Windows 两种环境下执行 14 项自动化测试并完成 12 个关键功能的浏览器级界面测试，全部通过；系统对陌生双栏论文与离线场景表现稳定。对照“文档解析智能体设计大赛”评审维度，基础部分全部达成，提高部分大部分达成；科学分析质量有待真实模型接入后的现场验收。
\end{abstract}

\section{引言}

阅读学术论文的核心困难不在于单句理解，而在于把握全文结构：研究问题是什么、论证如何展开、贡献与局限分别在哪里。大语言模型为自动结构化分析提供了可能，但直接调用模型存在三类风险：模型可能编造原文不存在的内容；分析往往只覆盖前几页而遗漏末页证据；生成的导图依赖在线服务，不可归档、不可离线分享。

“文档解析智能体设计大赛”将上述问题形式化为一条自动化流水线：PDF 输入 $\rightarrow$ 文本提取 $\rightarrow$ 论文结构分析 $\rightarrow$ Mermaid 导图生成 $\rightarrow$ 交互式 HTML 看板输出，并要求全程一键完成、不依赖外部 CDN、分析结果可回溯。本文报告我们按该要求实现的研脉系统，重点包括：（1）以来源块为单位的全文覆盖式分析设计\;\S\ref{sec:design}；（2）证据核验与完整性保障机制\;\S\ref{sec:evidence}；（3）自动化测试与端到端界面测试的结果\;\S\ref{sec:test}。

\section{系统设计}\label{sec:design}

系统由 PyMuPDF4LLM 按物理页提取文本\citep{pymupdf4llm}，复用 ScholarFlow 的数据模型与章节识别\citep{scholarflow}，改造 mindmap-generator 的递归导图生成方式\citep{mindmapgen}，经 FastAPI 提供本地上传服务\citep{fastapi}，并用 Playwright 驱动真实浏览器完成渲染校验\citep{playwright}。图~\ref{fig:pipeline} 展示整体流程。

\subsection{文档解析与来源分块}

解析阶段每页独立提取，异常页回退到 PyMuPDF 原生读取并给出阅读顺序警告；可提取文字不足的页面被标记为疑似扫描页，不静默跳过。论文标题在元数据缺失时按首页最大字号、水平走向与纵向位置启发式识别，避免将版权声明误认作标题。全文被切分为不超过 1200 字符的\textbf{来源块}，每个来源块携带物理页码、所属章节与稳定 ID（如 \texttt{p0003b0007}）。来源块按字符预算组成分析块，长度上限可配置，默认 10000 字符；实验表明 15 页双栏论文产生 254 个来源块、7 个分析块，末页内容同样进入分析覆盖记录。

\subsection{结构化分析与证据核验}\label{sec:evidence}

每个分析块单独请求模型，提示词要求返回固定结构的 JSON：发现列表，每项含节点名称、内容主题、九选一的类别标签、详细分析、读者友好解释、推断标记与证据引用。返回结果经过三层校验：JSON 结构与枚举合法性；证据 \texttt{source\_id} 必须属于当前分析块（而非全篇）；摘录经 Unicode NFKC 与空白归一化后必须能在来源块原文中逐字找到。校验失败时将错误回传模型修复，至多两次；仍失败则终止并保留已提取内容。

该设计有两个值得强调的取向。其一，\textbf{证据只证明引文存在，不证明结论成立}：界面上“摘录匹配”与“语义待核对”始终并列显示（图~\ref{fig:evidence}），推断性节点单独标记，未匹配摘录保留醒目标记而不伪造通过。其二，\textbf{全文覆盖优先}：所有分析块依次处理，不因已发现足够主题而提前结束，从机制上避免“只读摘要”类工具丢失末页局限的问题。

\subsection{合并、归纳与完整性检查}

去重采取保守策略：仅当类别、推断标记与详细分析三者归一化一致（或名称相似度超过 0.96）时才合并节点，语义相反的结论不会被错误聚合。主题归纳按批（每批不超过 24 个节点）请求模型将发现归入 2--6 个内容主题，不套用固定模板；每个输入节点 ID 必须恰好分配一次，最终树叶节点集合必须等于全部分析节点，否则终止导出。该完整性断言使合并环节的节点丢失从“静默缺陷”变为“显式错误”。

\subsection{导图校验与离线看板}

同一主题树生成 Mermaid mindmap 与 flowchart 两种格式，均先经真实 \texttt{mermaid.parse()} 校验\citep{mermaid}，再在 Chromium 中实际渲染为 SVG；标签含非常规字符导致解析失败时，按规则清洗标签结构字符后重试。看板为单文件 HTML：样式、交互脚本、Mermaid 渲染器、结构化数据与预渲染 SVG 全部内嵌，可选内嵌原始 PDF。生成的文件以 \texttt{file://} 直接打开即可使用，自动化测试验证离线模式下无任何 HTTP(S) 请求。

看板交互包括：节点索引与全文关键词搜索、局限与边界筛选、思维导图与结构关系图切换、拖拽平移与滚轮缩放、主题收起展开、节点详情与证据面板（页码按钮跳转原文并高亮摘录）、HTML/SVG/Mermaid/JSON 四种导出、深浅主题切换与移动端适配。

\subsection{本地服务与安全边界}

上传服务仅监听回环地址，校验 Host 与 Origin 头以阻断跨站请求与 DNS 重绑定；并发任务上限 3 个，单文件上限 80 MB，结果文件按白名单路由。API Key 仅经环境变量或 \texttt{.env} 注入，不写入源码、日志与导出文件；认证失败的响应正文不落盘。

系统目前存在四点局限。（1）\textbf{模型质量未经验收}：全部定量结果基于确定性模拟响应或抽取层核查，接入主办方 DeepSeek V4 Pro\citep{deepseek2024v3}后的科学分析准确率仍需人工核验；（2）\textbf{文本型 PDF 边界}：扫描件与图片型公式超出基础承诺，系统以显式警告而非静默降级处理；（3）\textbf{摘录匹配非蕴含判定}：证据核验只能确认引文存在，结论正确性仍需读者结合上下文判断；（4）\textbf{跨平台验证范围}：macOS 环境为本轮补充实测，正式提交材料仍以已声明的 Windows/Python~3.12 组合为准。后续计划接入独立语义核验通道，并探索分栏阅读顺序的显式建模。

\section{结论}

研脉系统以来源块与证据核验为中心组织整条流水线，将“模型会出错”作为设计前提而非异常路径，实现了从论文 PDF 到证据可溯、可离线使用的思维导图看板的一键转换。14 项自动化测试与 12 项界面功能测试全部通过，陌生论文抽取与离线场景核查未发现阻断性缺陷。系统已具备比赛基础部分的完整能力，剩余工作集中于真实模型接入后的质量验收。
